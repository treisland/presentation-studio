Use the feature PR's successful review artifact or build its source with `npm run build` and open dist/presentation-studio.html. Keep editable ZIP backups and use a separate browser profile with synthetic content. Record the exact commit, OS/browser, screen reader, display scaling and device; these are manual results rather than CI assertions.

1. Open Project settings → Background. Try Orbit, Aurora, Waves, Constellation, Geometric Drift and None. Confirm previews stage changes until Apply, Undo/Redo work, and Restore original orb restores the prior decoration without moving content.
2. Switch between light/dark themes and a custom palette. Confirm linked color roles update, custom colors remain, and Reset to theme reconnects a slot. Inspect title slides, dense text, tables/code, original images and real delivery video across the complete animation cycle.
3. Use Slide settings → Content → Background for one slide. Check presentation inheritance, explicit None, Static and Animated; slide reset; duplication; locks; independent grid visibility; quiet area; placement/scale/intensity/cycle duration and simpler rendering.
4. Edit text and drag/resize content beneath an effect. Navigator cards and editor backgrounds stay static. Preview motion animates only the explicit sample and stops when closed/changed. Viewers can pause motion independently; reduced-motion and Disable motion produce static equivalents. Check keyboard access, names/states, focus and screen-reader announcements.
5. Navigate between slides with matching backgrounds and verify continuity. Change effects and verify a clean deterministic restart. Hide/switch the browser tab, reopen projects and repeatedly open/close previews. Confirm no background motion consumes hidden/closed previews. Test a representative 50-slide deck and simultaneous video on the intended target hardware; record responsiveness and any limitations.
6. Export an editable v3 ZIP containing media, overrides and Undo/checkpoint history; restore in a clean profile. Verify IDs, effects/colors, media and Undo. Restore an existing v2 and legacy v1 project; an untouched v2 project still exports v2. Older Studio versions should reject a v3 file; never downgrade its version number. Unknown native/effect versions and invalid settings must leave current work intact.
7. Open playback and independent booth exports offline, including the actual intended delivery video/OBS if support is claimed. Verify matching colors, motion controls and content, and exclusion of private notes/history/omitted slides. Record actual OBS/browser-source versions and results; Chromium automation is separate evidence.
8. Download the AI instruction pack and use background-effects.json as an example. Validate an AI deck with defaults and slide overrides; review static previews before opening. Confirm unsupported presets, custom executable fields, malformed colors and future formats are rejected safely.
