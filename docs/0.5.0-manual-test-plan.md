# 0.5.0 first Portfolio checkpoint

The initial one-composition checkpoint passed maintainer review before expansion (PR #77). Recheck the expanded five-slide Portfolio starter/demo against the same workflows, especially each composition at laptop/desktop sizes and the four independent gallery crops. New automated results do not extend that earlier manual sign-off to newly added compositions or constitute release approval.

Review the first complete composition before expanding Portfolio/Comic/Editorial/Newsletter/Flyer. Record the tested commit, OS, browser and assistive technology versions with your result.

1. Open the built standalone HTML. New presentation offers Portfolio starter and finished example. Inspect both using defaults, then try the full setup flow and a dark theme. The starter has editable prompts and a visual drop target; the fictional finished example has complete text and an offline image.
2. Edit every text slot, image description and credits. Replace the image, compare Fit/Fill and crop, and add a second image cell. Check laptop and desktop viewports and keyboard selection. Theme changes should preserve composition and content.
3. Change an existing populated slide to Portfolio. Review the mapping before Apply. Include a table, command example, extra text and free blocks across your trial slides. Confirm nothing silently disappears; unmatched content remains on the slide with overflow guidance where needed. Undo restores the full prior slide in one step.
4. Lock a block, image, slide or project and try changing layout. It must refuse until unlocked. Cancel a default-text replacement and verify no changes. Accept one and use Undo/checkpoints to recover.
5. Try long titles and paragraphs. They must stay readable and be flagged for shortening/rearrangement, with no automatic tiny text. Check empty images and the title/body overlap warning.
6. Create another example after editing the first. Save-before-switch must preserve the first project; new project/slide IDs must differ. Reset the example copy: Cancel keeps edits, Accept restores its starting content, and Undo recovers edits. Creating another copy still uses the immutable library content.
7. Export editable and playback ZIPs. Extract into separate folders and reopen offline in a clean browser profile. Check image, text, theme, media identity, playback and editable restore. Open an older project and confirm its layout and recovery still work.
8. With a screen reader, check gallery labels/mapping/status, focus on dialogs and reading order: title, problem, approach, outcome, visual description, credits. Confirm keyboard-only editing and recovery. Run a real delivery video/OBS check if those environments are being claimed.

The first slice is a review build, not a release candidate. Remaining compositions, paired demos, the broader example gallery and walkthroughs follow this checkpoint. Do not treat automated results as manual sign-off.
