# 0.9.0-beta.1 — Editor workbench and Inspector workflows

Maintainer-approved beta of the combined 0.8.0 workbench and 0.9.0 Inspector/Layers changes. This prerelease builds on stable 0.7.0; no separate 0.8.0 release is backfilled. The integrated review build passed maintainer testing and the manual beta gates. See the [validation and authorization record](0.9.0-beta.1-validation.md).

## Included

- A polished canvas-first workbench with shared light/dark styles, responsive and resizable side panels, clearer primary actions, direct editable ZIP export and consistent Library/AI dialogs.
- Clear move/resize handles, explicit template customization and reset, Snap/alignment guidance, keyboard nudging and cancellation with locks and Undo preserved.
- A shared left Slides/Layers dock, readable names/previews, search and batch selection, eye/padlock icons, inline naming and existing drag/keyboard reordering.
- Compact Style summaries and on-demand Theme/Custom/Project color editing, with explicit scope, mixed-value handling, stale-draft protection and keyboard focus restoration.
- Separate Horizontal and Vertical slide-alignment controls for corners and edge centers without changing size, content or layer.
- Selection-driven Content editing for text, widgets, tables, code and media/grid cells. The legacy category row and generic object pickers are retired from the interface; scoped nested-field and panel alternatives retain legacy access. Code labels remain optional, and variants/defaults remain available.
- A persistent slide-notes drawer that retains object selection, preserves pending edits and follows the slide. Stale/deleted text targets cannot redirect editing to another object; file-picker cancellation preserves the editor, and short panels retain scrollable content.
- Layout-preserving hiding for template/Library content, with empty playback spacers and preserved media-layout settings while hidden text/media are omitted from playback and booth output.

Existing project IDs/formats, portable AI authoring, legacy imports, media/history, browser recovery, reusable components and editable/offline exports retain their existing contracts. The release-preparation PR changes metadata/documentation only; it introduces no runtime, dependency, workflow or saved-format changes beyond the approved feature PRs.

## Try the beta

Download `presentation-studio-v0.9.0-beta.1.zip`, extract it completely, then open `presentation-studio.html` or `presentation-studio-blank.html`. `studio-demo-editable.zip` is a separate editable demo. Keep a complete editable ZIP before trying a prerelease. Browser recovery is local to that profile and is separate from downloadable backups.

Review the [workbench guide](../editor-workbench.md), [Layers/Style/alignment guide](../layers-style-workflow.md) and [Content guide](../content-inspector.md). Export a complete editable ZIP for portable media and history, and reopen an extracted playback copy offline. Custom notes remain omitted from playback-only/booth exports.

## Limits and follow-up

- This is a beta prerelease, not a stable promotion. Final RC/stable artifact acceptance and separate release authorization remain required.
- Exact manual OS/browser/screen-reader/OBS versions and retained recording URLs were not supplied. The maintainer confirmed gate results; automated Windows/Linux checks do not certify a manual environment/version matrix.
- Live folder access, linked disk saves/reloads and native-picker investigation remain deferred (#117). Use individual JSON/editable-ZIP import and downloadable backups. No browser security settings need to be weakened.
- Legacy flow-based paragraph/list commands remain in a collapsed section because they are not identical to movable Library objects. Table structure uses the existing commands and counts, rather than a new destructive resize-on-input form.
- Existing limits remain: one native Code block per slide, one-level groups and free arrows without attached/routed connectors. Code is display/copy content and never executes. AI authoring validation does not establish factual accuracy, licensing or presentation fit.
- Visibility is not a secrecy or access-control boundary. Keep the editable project private when it contains material not intended for sharing; exported HTML and included content remain inspectable.

Publication requires the merged protected release plan, exact-main checks, an immutable tag, a successful tag release workflow and four complete SHA256-digested assets. Earlier tags and releases remain unchanged.
