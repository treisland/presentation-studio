## RC-specific gates

RC metadata build, unit tests, packaging and diff checks are recorded with actual outcomes in the preparation PR. Both hosted platform checks must succeed on the exact final PR head, then again on merged main. Prior beta success does not substitute for RC checks. The trusted-main runner may create only the unused immutable `v0.11.0-rc.1` tag after the explicit plan is merged and blockers/evidence/protections pass. The tag workflow rebuilds/checks/packages the candidate using the matched Playwright image.

Before publication, independently verify exactly four complete SHA256-digested RC downloads, embedded RC version/commit identity, ZIP CRC, packaged-payload equality and release docs. Publication remains a prerelease. Only after canonical publication may the explicit plan's beta-channel Docker/Pages targets promote RC: the separate beta website and the Docker version plus `rc` alias. Preserve previous beta aliases, stable/latest, npm, tags and published bytes. Verify actual deployed website bytes and registry digest/provenance receipts. Partial delivery failure remains visible and never authorizes bypassing a gate.
