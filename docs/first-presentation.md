# Your first presentation

Create → export → reopen. Start with the stable Studio app or its downloaded HTML.
This short path uses the existing example and ZIP menus; it needs no account.

## 1. Start from an example

Open Studio and choose **Edit**. Choose **Project → New presentation**, then
**Start from an example**. Preview **Studio**, **Portfolio** or **Newsletter**.
For Studio and Portfolio, choose the demo to explore finished content, or a
starter where offered to begin with editable prompts. Newsletter offers an editable
starter. Continue setup, name your presentation and use the defaults.

If another presentation has changes, use the save/export choice before switching,
or cancel and keep working. Starting from an example creates a separate project;
it does not turn the example into your only copy of an existing presentation.

- **Studio:** learn the editor with eight slides, an original diagram, a simple
  table and harmless display-only command text.
- **Portfolio:** tell a project story from problem to approach and evidence. Its
  community-library study is fictional sample content, not a customer result.
- **Newsletter:** organize a recurring update with editable sections and a shared
  visual. Replace the sample story and dates with your own.

See [Examples and layouts](examples.md) for the full collection and its original
content. Choose examples inside Studio; there is no special edit-example URL.

## 2. Make it yours

Choose a slide on the left. In **Edit blocks**, click its heading and replace the
sample words. Escape or Done finishes typing. Add a slide or change a layout when
needed; preview long content for overflow. Use Branding for your own colors/logo,
and Media settings for media you have permission to use.

Try **Present**, pause and move through the slides. Return to the editor to make
changes. Preview and export your actual media before relying on a delivery device.
The [quick start](quick-start.md) explains editing, branding, keyboard controls and
Media Focus in more detail.

## 3. Export an editable backup

Use **Export → Editable ZIP** in the editor’s export controls. Keep the downloaded
ZIP somewhere you can find again. It contains your editable project and the media
needed for its content and recovery data.

**A browser draft is not a backup.** Saved locally means this browser profile and
origin. Clearing site data, changing browsers or changing computers can make that
draft unavailable. Export an editable ZIP after important changes.

## 4. Reopen and check your copy

Open Studio in a separate browser profile for a restore check. Choose
**Presentations → Open ZIP / JSON** or **Project → Open file**, then select the
complete editable ZIP. Check your changed heading and media. Keep the original
profile and backup until the restored copy works.

Import the complete ZIP before exporting it again so recovery assets are loaded.
A project JSON file alone does not include image/video bytes. See
[Troubleshooting and recovery](troubleshooting.md) if content or assets are missing.

## 5. Present offline

Keep the editable backup, then export a **Playback ZIP** for delivery. Extract the
entire ZIP before opening its `index.html`; keep the accompanying assets beside it.
Disconnect the delivery machine from the network and check navigation, your actual
video/audio and any browser permission prompts. Reconnect when finished testing.

Editable ZIPs are for future changes and recovery. Playback ZIPs contain the visible
presentation and required media, excluding private notes and recovery history.
They are inspectable files, not access control. External links still need a network;
browser codec, autoplay, fullscreen and OBS behavior need your actual-device test.

You now have an editable backup and a separate delivery copy. Use
[Media compatibility](media-compatibility.md) before a real presentation and
[Import compatibility](import-compatibility.md) when opening another file version.
